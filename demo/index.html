The setup

  • Four engines behind one interface — a decision model (Jev), a frontier LLM run in the cloud (GLM, 5 samples per ask), the same-class model run locally (qwen via Ollama), and a scripted rule-mock. Every engine answered the exact same questions from the exact same case data.
  • 24 cases, 4 business flows — 6 broken CI runs, 6 buy-now-pay-later applications, 6 bounced installment payments, 6 dependency-upgrade PRs. Each case ships as a fixture: the full situation a real system would hand the engine.
  • The "right call" was decided by a person — before any engine ran, with the deciding evidence written into the case itself. If an expectation isn't backed by evidence in the fixture, it doesn't count.
  • 3 runs per engine per case — 216 asks total across the two comparison waves, plus dedicated probe batteries for calibration, consistency, latency, cost, and type-safety.

How runs are kept

  • Append-only committed waves — every run lands in results/ as JSON records and is never rewritten. Everything on this page is computed from those files.
  • Tagged, never clobbered — a new run gets a new tag (--tag=); an old result can't be overwritten by accident. Two overwriting incidents happened early; both files were restored byte-identical from git and the guards came after.
  • Pre-registered predictions — for the evidence test, the expected outcome was written down and committed before the first live call.
  • The mock is the scoring anchor — its answers replay the expectations, so it scores 24/24 by construction. It exists to prove the scoring works, not to compete.
